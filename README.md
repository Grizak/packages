# Grizak Packages Repository

This repository hosts package repositories for multiple Linux distributions and architectures:

- **Debian / Ubuntu** (`apt`)
- **Fedora / RHEL / Rocky / AlmaLinux** (`rpm`)
- **Arch Linux** (`pacman`)

Packages are published automatically through GitHub Actions and served via GitHub Pages.

## Supported Platforms

| Distribution Family | Architectures            |
| ------------------- | ------------------------ |
| Debian / Ubuntu     | amd64, arm64             |
| Fedora / RHEL       | Depends on package build |
| Arch Linux          | x86_64                   |

# Repository URLs

## APT (Debian / Ubuntu)

Repository URL:

```text
https://pkg.isaksweb.xyz/apt
```

Import the signing key:

```bash
curl -fsSL https://pkg.isaksweb.xyz/key.asc | \
sudo gpg --dearmor -o /usr/share/keyrings/grizak-archive-keyring.gpg
```

Add the repository:

```bash
echo "deb [signed-by=/usr/share/keyrings/grizak-archive-keyring.gpg] https://pkg.isaksweb.xyz/apt stable main" | \
sudo tee /etc/apt/sources.list.d/grizak.list
```

Update package metadata:

```bash
sudo apt update
```

Install packages:

```bash
sudo apt install <package-name>
```

---

## RPM (Fedora / RHEL / Rocky / AlmaLinux)

Import the signing key:

```bash
sudo rpm --import https://pkg.isaksweb.xyz/key.asc
```

Create a repository definition:

```ini
[grizak]
name=Grizak Packages
baseurl=https://pkg.isaksweb.xyz/rpm
enabled=1
gpgcheck=1
repo_gpgcheck=1
gpgkey=https://pkg.isaksweb.xyz/key.asc
```

Save this as:

```text
/etc/yum.repos.d/grizak.repo
```

Install packages:

```bash
sudo dnf install <package-name>
```

## Arch Linux

Download the repository signing key and check its fingerprint against the one published at https://pkg.isaksweb.xyz/fingerprint.txt:

```bash
curl -fsSL https://pkg.isaksweb.xyz/key.asc -o grizak.asc
curl -fsSL https://pkg.isaksweb.xyz/fingerprint.txt
gpg --with-colons --show-keys grizak.asc | awk -F: '/^fpr:/ {print $10; exit}'
```

The two fingerprints printed by the last two commands must match. If they don't, stop and don't continue.

Import the key into pacman's keyring and mark it as trusted:

```bash
FPR=$(gpg --with-colons --show-keys grizak.asc | awk -F: '/^fpr:/ {print $10; exit}')
sudo pacman-key --add grizak.asc
sudo pacman-key --lsign-key "$FPR"
```

Add the repository to `/etc/pacman.conf`:

```ini
[grizak]
SigLevel = Required DatabaseOptional
Server = https://pkg.isaksweb.xyz/arch/$arch
```

Refresh package databases:

```bash
sudo pacman -Sy
```

Install packages:

```bash
sudo pacman -S <package-name>
```

# Publishing Packages

Publishing is automated.

A package build workflow should:

1. Build one or more package formats:
   - `.deb`
   - `.rpm`
   - `.pkg.tar.zst`

2. Create a GitHub Release containing those artifacts.
3. Trigger a `repository_dispatch` event with:

```json
{
  "event_type": "publish",
  "client_payload": {
    "tag": "v1.2.3"
  }
}
```

The ingest workflow will:

1. Download package artifacts from the release.
2. Update APT repository metadata.
3. Update RPM repository metadata.
4. Update Arch repository metadata.
5. Sign repository indexes.
6. Publish the updated repository to GitHub Pages.
7. Delete the temporary staging release.

Publishes are serialized to prevent repository index corruption from concurrent updates.

# Repository Layout

```text
apt/
├── pool/
└── dists/

rpm/
└── repodata/

arch/
└── x86_64/

key.asc
```

- `apt/` contains Debian repository metadata and packages.
- `rpm/` contains RPM repository metadata generated by `createrepo_c`.
- `arch/` contains the Pacman repository database and package files.
- `key.asc` is the public signing key used to verify repository metadata.

---

# Security

All repository metadata is cryptographically signed using GPG.

Verification mechanisms:

| Repository Type | Verification                            |
| --------------- | --------------------------------------- |
| APT             | InRelease + Release.gpg                 |
| RPM             | Signed repomd.xml                       |
| Arch            | Signed packages and repository database |

Users should always import the repository signing key before installing packages.
